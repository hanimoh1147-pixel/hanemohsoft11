# مشروع هاني سوفت — النسخة الأساسية القابلة للتهيئة

## ما الموجود؟
- واجهة عربية RTL بتصميم أسود وذهبي.
- تسجيل حساب بالبريد واسم مستخدم وكلمة مرور، وتسجيل الدخول بالبريد أو اسم المستخدم.
- كتالوج خدمات، إنشاء طلب وخصم الرصيد داخل معاملة قاعدة بيانات واحدة.
- محفظة وسجل حركات وتحويل رصيد بين العملاء.
- طلبات شحن معلقة؛ اعتماد الشحن مقصور على المالك/المسؤول صاحب صلاحية `review_deposits`.
- تقييم الطلب بعد اكتماله.
- لوحة إدارة أولية لإضافة الخدمات وتغيير حالة الطلب واعتماد طلب الشحن.
- SQL مع RLS وسياسات وصلاحيات.

## مهم قبل الاستخدام العام
هذه نسخة أساس تشغيلية تحتاج إعدادًا واختبارًا داخل مشروع Supabase. ليست منصة دفع إلكتروني مكتملة، ولا يوجد فيها حتى الآن تكامل مع شركات السيرفرات أو API لأدوات السوفت وير. لا تعرض أي خدمة باعتبارها آلية حتى تربط API رسميًا ومصرحًا به لها. شحن الرصيد لا يُعتمد إلا بعد التحقق الفعلي من الدفع.

## 1) إنشاء Supabase
1. افتح https://supabase.com وأنشئ مشروعًا جديدًا.
2. من SQL Editor افتح استعلامًا جديدًا والصق كامل محتوى `schema.sql` ثم Run.
3. من Project Settings > API/Connect انسخ Project URL والمفتاح العام (Publishable أو anon القديم).
4. افتح `config.js` وضع القيم في `SUPABASE_URL` و`SUPABASE_ANON_KEY`.
5. لا تضع `service_role` أو `secret key` في `config.js` أو GitHub. هذه المفاتيح تملك صلاحيات عالية.
6. في Authentication > URL Configuration أضف رابط GitHub Pages إلى Site URL وRedirect URLs.
7. اختبر إنشاء حساب جديد؛ إذا كان تأكيد البريد مفعّلًا، أكّد البريد قبل الدخول.

### تسجيل الدخول باسم المستخدم
انشر الدالة الخلفية من مجلد `supabase/functions/username-login` باستخدام Supabase CLI. عيّن أسرار الدالة في مشروع Supabase: `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`؛ لا تضع المفتاح السري في GitHub أو `config.js`. الدالة تعيد جلسة تسجيل الدخول، ولا تعرض البريد المقابل لاسم المستخدم للواجهة. فعّل حدود محاولات الدخول وراقب سجلات الدالة قبل الاستخدام العام.

## 2) تعيين المالك والمسؤول
1. أنشئ حساب المالك من الموقع باستخدام بريد المالك الحقيقي.
2. في SQL Editor نفّذ الأمر التالي مع استبدال البريد:
```sql
update public.profiles p
set role='owner',
    permissions=array['manage_services','review_deposits','manage_orders','manage_reviews']
from auth.users u
where p.id=u.id and lower(u.email)=lower('OWNER_EMAIL_HERE');
```
3. أنشئ حساب المسؤول ثم نفّذ أمرًا مشابهًا مع `role='admin'` والبريد الصحيح. أعطه الصلاحيات التي يحتاجها فقط، مثل:
```sql
update public.profiles p
set role='admin',
    permissions=array['manage_services','review_deposits','manage_orders']
from auth.users u
where p.id=u.id and lower(u.email)=lower('ADMIN_EMAIL_HERE');
```
4. رقم التواصل للمالك `+84562812172` وللمسؤول `+966 55 492 1073` ظاهر في تذييل الواجهة فقط. الأرقام لا تثبت هوية صاحب الحساب ولا تمنح صلاحيات تلقائيًا.

## 3) إضافة خدمات وأسعار
- سجّل الدخول بحساب يملك `manage_services`.
- أضف الخدمات من لوحة الإدارة. أسعار الخدمات بالعملة المسجلة لكل خدمة.
- ملاحظة تصميمية: رصيد المحفظة والتحويلات في هذه النسخة بالدولار USD فقط. يمكن عرض خدمة أو طلب شحن بعملة SDG، لكن إجراء الشراء أو اعتماد الشحن يرفض عملة غير USD صراحةً حتى لا يختلط رصيد بعملتين. قبل الإطلاق، اجعل خدمات الشراء وطلبات الشحن بالدولار فقط أو أضف محفظة منفصلة لكل عملة وسعر صرف موثق.

## 4) نشر الواجهة على GitHub Pages
1. أنشئ مستودع GitHub جديدًا.
2. ارفع `index.html`, `style.css`, `app.js`, `config.js`.
3. من Settings > Pages اختر النشر من الفرع الرئيسي ومن مجلد الجذر `/`.
4. افتح الرابط بعد النشر. نشر الملفات لا يثبت وحده أن Supabase مضبوط؛ اختبر التسجيل والدخول والخدمات والمحفظة والطلبات.

## 5) الدفع الإلكتروني الحقيقي
النسخة الحالية تسجل `deposit_requests` فقط. لا توجد عملية دفع فعلية. لربط بوابة دفع:
1. اختر مزودًا يدعم بلد نشاطك وعملة التسوية (مثلاً مزود محلي أو مزود عالمي متاح قانونيًا لحسابك).
2. نفّذ إنشاء جلسة الدفع والتحقق من webhook داخل Supabase Edge Function أو خادم موثوق.
3. خزّن مفاتيح المزود كـ Supabase secrets فقط.
4. لا تضف الرصيد اعتمادًا على رجوع المتصفح أو صورة إيصال. يجب التحقق من webhook موقّع ومن رقم العملية والمبلغ والعملة وحالة الدفع، مع منع معالجة العملية مرتين.
5. أضف مرجع عملية فريدًا وقيود idempotency قبل التشغيل العام.

## 6) تكامل سيرفرات السوفت وير
لكل مزود خدمة خارجي تحتاج API رسميًا، حساب تاجر، توثيقًا، تسعيرًا، وطريقة استعلام عن حالة المهمة. يضاف التكامل في Edge Functions وليس في JavaScript العام، ولا تُرسل مفاتيح مزود الخدمة للمتصفح. الخدمات التي تتطلب إثبات ملكية الجهاز أو تصريحًا يجب أن تُقدّم وفق شروط المزود والقوانين المعمول بها.

## 7) أمان وفحوصات قبل إطلاق حقيقي
- فعّل MFA للمالك والمسؤول، وكلمات مرور قوية، وحدود محاولات الدخول.
- فعّل حماية تسريب كلمات المرور إن كانت متاحة في خطتك.
- راجع Auth rate limits، البريد الإلكتروني، نسخ احتياطية، التنبيهات والسجلات.
- اختبر على حسابين: تحويل صحيح، تحويل لرصيد غير كافٍ، تحويل لنفس المستخدم، إنشاء طلب دون رصيد، اعتماد طلب شحن مرتين، وقراءة بيانات مستخدم آخر.
- راجع سياسات RLS بعد أي تغيير. لا تعتمد على إخفاء عناصر الواجهة لحماية العمليات.
- احتفظ بسجل مالي لا يسمح للعميل بتعديله. راجع سياسة الاسترداد والنزاعات ومكافحة الاحتيال.
- لا تستخدم أرصدة بأكثر من عملة دون دفتر محفظة مستقل لكل عملة وأسعار صرف موثقة.

## قيود معلنة في هذه النسخة
- تسجيل الدخول باسم المستخدم يعتمد على Edge Function تتطلب أسرار Supabase محفوظة في الخادم. يجب ضبط rate limiting/مراقبة محاولات الدخول قبل الاستخدام العام.
- شاشة الشحن الحالية طلب مراجعة يدوية، وليست بوابة دفع.
- لا يوجد API متصل بمزودي خدمات الهواتف بعد.
- زر تغيير حالة الطلب لا ينفّذ الخدمة الخارجية تلقائيًا.
- النسخة الأساسية تحتاج اختبارًا فعليًا داخل مشروعك قبل وصفها بأنها جاهزة للإنتاج.

## تحديث الردود والتعليقات لكل طلب
1. افتح Supabase Dashboard ثم SQL Editor.
2. شغّل ملف `schema.sql` المحدّث كاملًا. الأوامر الجديدة تضيف حقول التعليق وبريد الرد والرد الرسمي، وتضيف دوال آمنة للحفظ.
3. ارفع الملفات المحدّثة `index.html`, `app.js`, `style.css`, `schema.sql` إلى المستودع نفسه على GitHub، مع الحفاظ على `config.js` الذي يحتوي إعدادات مشروعك الصحيحة.
4. سجّل الدخول بحساب عميل: داخل كل طلب توجد خانة تعليق وخانة بريد إلكتروني، ويظهر رد الإدارة عند حفظه.
5. سجّل الدخول بحساب أدمن لديه صلاحية `manage_orders`: ستظهر التعليقات والبريد وخانة الرد الرسمي المستقلة لكل طلب.

تنبيه: إرسال الرد بالبريد الإلكتروني تلقائيًا غير مفعّل في هذه الإضافة؛ البريد يُحفظ في الطلب ويظهر للأدمن، والرد يظهر داخل حساب العميل. لإرسال إشعار بريد فعلي يلزم إعداد خدمة بريد وربطها بدالة آمنة في Supabase.
